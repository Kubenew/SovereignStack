## Overview

[ISO 20022](https://www.iso20022.org/) is the global standard for financial messaging. It defines a common platform for the development of messages using a modelling methodology, a central dictionary, and a set of XML and ASN.1 design rules.

SovereignStack maps its `ss-economy` types and `payment://` / `settlement://` URI schemes to ISO 20022 message types, enabling sovereign agents to participate in the global financial messaging network while maintaining full provenance and policy enforcement.

## Message Category Mapping

### Payments (pacs — Payments Clearing and Settlement)

| ISO 20022 Message | Description | SovereignStack Mapping |
|-------------------|-------------|------------------------|
| `pacs.008` | FIToFI Customer Credit Transfer | `Payment` with `PaymentMethod::BankTransfer` |
| `pacs.002` | FIToFI Payment Status Report | `PaymentStatus` enum transitions |
| `pacs.004` | Payment Return | `PaymentGateway::reverse()` |
| `pacs.009` | FIToFI Financial Institution Credit Transfer | `Payment` between `bank://` twins |
| `pacs.010` | FI Direct Debit | `PaymentRequest` with debit indicator |

### Payment Initiation (pain)

| ISO 20022 Message | Description | SovereignStack Mapping |
|-------------------|-------------|------------------------|
| `pain.001` | Customer Credit Transfer Initiation | `PaymentRequest` submission |
| `pain.002` | Customer Payment Status Report | `PaymentGateway::status()` response |
| `pain.008` | Customer Direct Debit Initiation | `PaymentRequest` with debit method |
| `pain.013` | Creditor Payment Activation Request | Agent-initiated payment workflow |

### Cash Management (camt)

| ISO 20022 Message | Description | SovereignStack Mapping |
|-------------------|-------------|------------------------|
| `camt.052` | Bank-to-Customer Account Report | `TreasuryManager::cash_position()` |
| `camt.053` | Bank-to-Customer Statement | `TreasuryAccount` balance history |
| `camt.054` | Bank-to-Customer Debit/Credit Notification | Event on `treasury://` URI |
| `camt.060` | Account Reporting Request | Query on `treasury://` entity |

### Securities (sese / semt)

| ISO 20022 Message | Description | SovereignStack Mapping |
|-------------------|-------------|------------------------|
| `sese.023` | Securities Settlement Instruction | `SettlementInstruction` with `DvP` |
| `sese.024` | Securities Settlement Status | `SettlementStatus` transitions |
| `semt.002` | Securities Balance Custody Report | `Asset` positions via `AssetRegistry` |

## Data Type Mapping

| ISO 20022 Type | SovereignStack Type |
|----------------|---------------------|
| `ActiveCurrencyAndAmount` | `Money` (amount + currency + decimals) |
| `ISODate` / `ISODateTime` | `chrono::DateTime<Utc>` |
| `IBAN` | String field on `TreasuryAccount` |
| `BICFIIdentifier` | String field on `bank://` twin identity |
| `ISIN` | `Asset::isin` field |
| `PartyIdentification` | `person://` or `company://` URI |
| `FinancialInstitutionIdentification` | `bank://` URI |

## Example: Cross-Border Payment

### ISO 20022 `pain.001` → SovereignStack

```
ISO 20022 pain.001 (Customer Credit Transfer Initiation)
    ↓
PaymentRequest {
    payer: "person://alice",
    payee: "person://bob",
    amount: Money { amount: 100000, currency: "EUR", decimals: 2 },
    method: PaymentMethod::BankTransfer { network: "SWIFT" },
    iso20022_type: Some("pain.001"),
    reference: Some("INV-2026-0042"),
}
    ↓
PaymentGateway::initiate(request) → Payment { uri: "payment://swift/pacs008-001", ... }
    ↓
ISO 20022 pacs.008 emitted on Event Bus
```

## Implementation Notes

1. **Serialization**: ISO 20022 messages use XML. SovereignStack uses JSON internally. Adapters convert between formats at the federation gateway.
2. **Provenance**: Every ISO 20022 message processed through SovereignStack gets a provenance entry with cryptographic signature.
3. **Policy enforcement**: Payments are validated against active `policy://` rules before ISO 20022 message generation.
4. **Compliance**: The `fin_compliance` module can validate that generated messages meet regulatory requirements (PSD2, SEPA rulebook).
